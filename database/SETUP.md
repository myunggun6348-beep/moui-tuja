# 이메일 계정 저장 연결

이 저장소는 가상 종목으로 연습하는 앱입니다. 실제 주식 주문을 보내지 않습니다.

1. `moui-tuja` 전용 Supabase 프로젝트를 만든 뒤 Vercel **Preview**에 연결합니다. 기존 다른 앱의 저장소는 사용하지 않습니다.
2. Supabase SQL Editor에서 `schema.sql`을 한 번 실행합니다. 계정은 현금 1,000만 원과 보유 주식 0주로 시작합니다.
3. Vercel Preview에 `NEXT_PUBLIC_SUPABASE_URL`과 `NEXT_PUBLIC_SUPABASE_ANON_KEY`를 설정합니다. anon 키 또는 publishable 키만 사용합니다. service_role, secret 키는 브라우저에 제공하지 않습니다.
4. Supabase Authentication의 Site URL을 고정 미리보기의 `/login.html`로 설정합니다. 기본 메일의 로그인 링크를 사용하며, PKCE로 요청한 브라우저를 확인한 뒤 인증 코드를 세션으로 교환합니다. 별도 SMTP를 연결하기 전에는 무료 기본 이메일 템플릿을 바꾸지 않습니다.
5. Supabase 기본 이메일 발송은 팀에 등록된 주소 등 제한이 있습니다. 다른 사용자가 가입하려면 별도 SMTP 발송 서비스와 발신 주소를 연결해야 합니다. 연결 전에는 제한을 우회하거나 이메일 확인을 끄지 않습니다.
6. Preview를 재배포하고 실제 이메일 인증을 사용자가 완료합니다. 별도 두 계정으로 데이터 분리, 재로그인, 매수·매도, 동시 주문과 실패 시나리오를 확인합니다.

계정 기록은 데이터베이스에 남습니다. 로그인 세션만 탭의 sessionStorage에 보관하며, 브라우저를 닫은 후에는 다시 인증할 수 있습니다. 이메일이나 OTP는 브라우저 저장소에 보관하지 않습니다. 메일 요청의 PKCE 검증값만 localStorage에 임시 보관하며 인증 후 삭제합니다. 로그인 링크는 요청한 브라우저에서 열어야 합니다.

기존 닉네임·PIN 계정과 localStorage의 연습 기록은 자동 이전되지 않습니다. 로그인 없이 화면 연습을 선택하면 기존 브라우저 기록을 계속 사용합니다.

DB는 사용자별 조회에 RLS를 적용하고 일반 사용자의 직접 수정은 차단합니다. 주문 함수가 로그인 사용자 ID를 확인하고, 계정 행 잠금, 최신 버전 검사 및 요청 ID 중복 방지로 현금·수량·주문내역을 하나의 트랜잭션으로 갱신합니다.
